# 技術選定メモ: 地理座標に忠実なインタラクティブ路線図

## 結論

| 項目 | 採用 | 理由 |
|---|---|---|
| 地図描画 | **MapLibre GL JS** | WebGL描画で全国規模でも軽い。`setFilter` / `feature-state` で「この線だけ表示」「ハイライト」が標準機能。無料・OSS |
| ベースマップ | **OpenFreeMap (Positron)** または **地理院タイル 淡色地図** | APIキー不要・無料。淡い色味なので路線色が埋もれない |
| 路線・駅データ | **国土数値情報 鉄道データ (N02)** | 国交省公式。全国の路線ポリライン＋駅が GeoJSON で落とせる。路線名・運営会社つき |
| 路線カラー・駅よみ | **駅データ.jp** (無料, CC BY 4.0) を N02 に突き合わせ | N02 には色も読みも無い。かな検索と路線色に必要 |
| 検索 | **Fuse.js** | あいまい検索。かな・漢字・ローマ字を一括インデックスできる |
| ビルド | **Vite + TypeScript** (フレームワーク無し) | UIは検索ボックスとフィルタパネル程度。Reactは不要、必要になったら Preact を足す |
| ホスティング | **GitHub Pages** | 完全静的。サーバー不要 |

## 検討した他の候補と、選ばなかった理由

- **Leaflet**: 一番お手軽。ただし SVG/Canvas 描画なので、首都圏全路線＋駅ラベルを出すとパン・ズームがもたつく。路線の絞り込みも DOM の付け外しになり、MapLibre の式ベースフィルタより書きづらい。関西・首都圏だけに限定するなら十分アリだが、将来の拡張を考えると MapLibre。
- **D3 (d3-geo)**: ベースマップ無しの「抽象的だけど座標は正確」なスタイルを作るならこれ。見た目の自由度は最高。ただしズーム・パン・ラベル衝突回避・タイル読み込みを全部自作することになる。「デザインはそこまで拘らない」とのことなので割に合わない。
- **deck.gl**: 数百万点を描くための道具。鉄道路線の規模ではオーバーキル。
- **Google Maps / Mapbox**: 商用APIキー・課金が絡む。OSS で足りるのにわざわざ依存を増やす理由がない。
- **ODPT (公共交通オープンデータ)**: 路線色やよみも揃っていて質は高いが、登録制で対象が関東中心。全国をカバーする N02 を主軸にして、必要なら補助的に使う。

## 視認性のための設計方針

- ベースマップは彩度を落とした淡色（Positron / 淡色地図）。路線色が主役になるようにする。
- 路線は **白い縁取り (casing) + 路線色** の2レイヤー。地図の道路や川と区別がつく。
- 線幅・駅の円の半径はズームに応じて `interpolate` で可変。広域では細く、拡大すると太く。
- 駅は白塗り＋路線色の縁。乗換駅は少し大きく。
- ラベル (symbol layer) は `text-halo` を太めに。MapLibre が衝突回避してくれる。
- 「この線だけ表示」は他路線を消すのではなく **透明度 0.15 程度に落とす**。地理的な文脈が残って読みやすい。完全非表示はトグルで切替可能にする。
- hover / 選択は `feature-state` で色や太さを変える（再描画なしで速い）。

## 機能と実装方法

| 機能 | 実装 |
|---|---|
| 路線名・駅名で検索 | Fuse.js で `{ 路線名, 運営会社, 駅名, よみ }` をインデックス。候補をリスト表示 |
| 路線を選ぶとその線だけ強調 | `map.setFilter('rail-line', ['==', ['get','line_id'], id])` または全路線レイヤーの opacity を `case` 式で切替 |
| 事業者で絞り込み | `['in', ['get','operator'], ['literal', [...]]]` のフィルタ式 |
| 駅をクリック → 通っている路線一覧 | 前処理で駅→路線IDの対応表を JSON に持たせておく |
| 選択路線にズーム | 前処理で各路線の bbox を持ち、`map.fitBounds` |
| URL で状態共有 | `?lines=a,b&station=xyz` をクエリに同期 |

## データパイプライン (Node スクリプト, `scripts/build-data.ts`)

1. N02 の `RailroadSection` / `Station` GeoJSON を取得。
2. 日本語キー（路線名、運営会社…）を英語キーに正規化。`line_id = operator + line_name` で一意化。
3. 駅データ.jp の `line.csv` (`line_color_c`) と `station.csv` (よみ) を路線名・駅名で突合。マッチしない分は手動マッピング表 (`data/overrides.json`) で補う。
4. mapshaper か turf で軽く簡略化（全国だと数十MBあるので、`-simplify 10%` 程度）。
5. 出力: `public/data/lines.geojson`, `public/data/stations.geojson`, `public/data/index.json` (検索用の軽量インデックス + bbox + 駅⇄路線対応)。

全国を一枚の GeoJSON で読むと重ければ、`tippecanoe` で PMTiles 化して静的配信に切り替える（MapLibre はそのまま読める）。初手は GeoJSON で十分。

## 対象範囲の決め方

まず **首都圏 (1都3県) か特定都市圏** で作って、動いたら全国に広げるのが現実的。N02 は全国分がまとめて来るので、前処理で都道府県コードやbboxで切り出す。

## ざっくり工数感

- データパイプライン: 1〜2日（突合の手作業が一番かかる）
- 地図表示＋スタイル: 半日〜1日
- 検索・絞り込み UI: 1日
- 磨き込み (ラベル、乗換駅、URL同期): 1日
